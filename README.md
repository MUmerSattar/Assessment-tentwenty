# SauceDemo E2E Automation Suite

Professional Playwright JavaScript end-to-end test automation for SauceDemo application.

## Project Overview

Automated test suite validates the complete purchase flow: authentication, inventory interaction, cart management, checkout process, and order confirmation. Built with Playwright using Page Object Model (POM) design pattern for maintainability and scalability.

**Target:** https://www.saucedemo.com/
**Test Credentials:** `standard_user` / `secret_sauce`
**Language:** JavaScript (Node.js CommonJS)
**Framework:** @playwright/test

## Prerequisites

- Node.js v18 or higher
- npm v9 or higher

- `[data-test="shopping-cart-badge"]` - Cart badge counter

   - Playwright test runner configuration with Chromium/Firefox

### Manual QA Reviews & Corrections Applied

1. **Locator Strategy Refinement**
   - **Initial Attempt:** XPath-based selectors (fragile to DOM changes)
   - **Correction:** Replaced all XPaths with robust `data-test` attribute selectors
   - **Reason:** Sauce Labs application uses explicit `data-test` attributes; these are stable, maintainable, and avoid brittle structural dependencies

2. **Assertion Pattern Enforcement**
   - **Initial Attempt:** Used implicit waits and direct comparisons (`page.waitForTimeout(500)`)
   - **Correction:** Enforced Playwright web-first auto-waiting assertions (`expect(locator).toHaveText()`, `expect(page).toHaveURL()`)
   - **Reason:** Auto-waiting prevents flakiness, improves reliability, avoids race conditions

3. **Cart Badge Verification**
   - **Initial Attempt:** Simple text comparison without type safety
   - **Correction:** Used `toHaveText('1')` assertion for built-in waiting and retry logic
   - **Reason:** Ensures element is stable before assertion; Playwright retries automatically

4. **Form Interaction Patterns**
   - **Initial Attempt:** Sequential `.fill()` calls with implicit timing assumptions
   - **Correction:** Maintained `.fill()` calls but ensured all subsequent actions auto-wait on page state
   - **Reason:** Playwright's auto-waiting handles timing; explicit waits not needed

5. **Page Navigation Validation**
   - **Initial Attempt:** No URL verification between steps
   - **Correction:** Added `expect(page).toHaveURL(/.*pattern/)` after critical navigation actions
   - **Reason:** Confirms page transitions completed; detects unexpected redirects or failures

### Limitations & Risks of Automation Suite

1. **Mock Frontend Data Dependency**
   - SauceDemo is a demo application with static product catalog
   - Real-world testing would require dynamic data setup/teardown
   - Mitigation: Suite validates against known, stable product names ("Sauce Labs Backpack")

2. **Static Test Credentials**
   - Uses hardcoded credentials (`standard_user` / `secret_sauce`)
   - Production suites should externalize credentials via environment variables
   - Risk: Credentials visible in repository; mitigate via .gitignore and env-based injection

3. **Single User Journey**
   - Suite tests only standard_user path
   - Does not cover locked_out_user, performance_glitch_user, or other user types
   - Expansion: Add parameterized tests for multiple user scenarios

4. **No Network Failure Scenarios**
   - Does not test offline behavior, timeouts, or API failures
   - No chaos engineering or resilience testing
   - Mitigation: Extend suite with network interception tests using `page.route()`

5. **Limited Error Handling Validation**
   - Does not verify error messages for invalid input (e.g., missing ZIP code)
   - Real suite should include negative test cases
   - Recommendation: Add dedicated test for validation error flows

6. **Cross-Browser Limitations**
   - Tests Chromium and Firefox; does not cover Safari or mobile browsers
   - SauceDemo responsive design not validated
   - Mitigation: Add webkit browser profile and viewport-specific tests

7. **No Accessibility Testing**
   - Suite does not validate keyboard navigation, or screen reader compatibility
   - Recommendation: Integrate `@axe-core/playwright` for automated accessibility checks

8. **Hard-Coded Test Data**
   - Checkout form uses fixed values ("John", "Doe", "12345")
   - Parameterized tests would improve coverage (edge cases, international formats)
   - Recommendation: Use Playwright's `test.describe.each()` or data-driven approach

9. **Performance Metrics Not Captured**
   - No measurement of page load times, interaction latency
   - Real-world suites should track performance baseline metrics
   - Mitigation: Use Playwright's `page.metrics()` and Performance API integration

10. **Test Isolation & Cleanup**
    - Suite does not clear cart/account state between runs
    - Subsequent test runs may fail if state persists
    - Mitigation: Extend `beforeEach` to reset state or implement logout in `afterEach`

## Known Issues & Troubleshooting

**Tests timeout at checkout step:**
- Verify network connectivity to saucedemo.com
- Increase timeout in `playwright.config.js`: `timeout: 30000` (default 30s often sufficient)

**Cart badge not visible:**
- Confirm item was added to cart in previous step
- Check for JavaScript errors in browser console

**Flaky tests during cart navigation:**
- SauceDemo occasionally has latency; Playwright auto-waits mitigate most cases
- If persistent, increase `expect()` timeout: `expect(element).toBeVisible({timeout: 10000})`
